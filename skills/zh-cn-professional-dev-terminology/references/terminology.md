# 中文专业开发术语规范

本文件用于中文汇报、流程说明和技术文档的输出层本地化。它不定义开发流程，
不改变内部状态，也不参与工具调用或技术决策。

## 使用原则

1. 先确认英文概念在当前语境中的真实含义，再选择中文术语。
2. 专业术语应准确、稳定，不为了口语化而合并不同工程概念。
3. 内部字段、命令、状态值和错误信息保持原样，中文只作为说明。
4. 首次出现且可能有歧义时，可使用“中文术语（英文术语）”。
5. 找不到可靠译法时保留英文，并补充简短中文解释。

## 核心术语

| 英文概念 | 推荐中文 | 使用说明 |
|---|---|---|
| `patch` | 补丁、代码修复 | 名词或版本变更可用“补丁”；开发动作可用“代码修复”。不要泛化成测试或发布动作。 |
| `code review` | 代码评审 | 指对代码或稳定差异的评审，不应翻译成“质量门”或“测试验收”。 |
| `integration test` | 集成测试 | 指模块或服务组合后的测试。团队共同对接和排查过程可称“联调”，但两者不应无条件互换。 |
| `regression test` | 回归测试 | 指验证已有功能未因变更而退化，不等同于集成测试。 |
| `quality gate` | 质量门禁、质量门 | 指必须满足的质量条件，不等同于一次测试或业务验收。 |
| `candidate` | 候选版本、候选发布版本 | 表示待评估或待发布的版本。“待上线”是状态说明，不是该术语本身。 |
| `preflight` | 发布前预检 | 目标明确为生产环境时可写“生产发布前预检”。不要将普通开发检查称为生产预检。 |
| `artifact` | 构建产物 | 可包含镜像、压缩包、安装包、静态资源等，不应一律翻译成“镜像”。 |
| `attestation` | 构建来源证明、构建来源与版本对应证明 | 用于说明源码、构建过程和产物之间的对应关系。必要时首次保留英文。 |
| `checkpoint` | 检查点、恢复检查点 | 用于记录可恢复的流程位置，不等同于回滚版本。 |
| `smoke test` | 冒烟测试 | 指快速验证关键能力是否基本可用，不等同于完整业务验收。 |
| `acceptance` | 业务验收 | 指确认实际业务路径和预期结果，不等同于冒烟测试或质量门禁。 |
| `rollback` | 回滚、恢复上一稳定版本 | “回滚”表示动作；强调结果时可写“恢复上一稳定版本”。 |

## 常用配套术语

| 英文概念 | 推荐中文 | 使用说明 |
|---|---|---|
| `development` | 开发 | 表示实现和修复活动，不自动包含发布。 |
| `implementation` | 实现 | 表示具体技术实现，不应统一翻译成“开发流程”。 |
| `build` | 构建 | 指把源码转换为可运行或可分发产物的过程。 |
| `release` | 发布、发版 | 指版本进入可交付或生产使用状态的整体活动。 |
| `deployment` | 部署 | 指把构建产物应用到目标环境的技术动作。部署成功不自动等于发布完成。 |
| `go live` | 上线 | 指业务或用户可正式使用，通常需要结合部署和验收结果判断。 |
| `hotfix` | 紧急修复、热修复 | 仅用于需要快速处理的线上问题，不应用于普通代码修复。 |
| `workaround` | 临时规避方案 | 表示绕开问题的临时措施，不应表述为根因修复。 |
| `fallback` | 备用路径、降级方案 | 根据语境选择；备用实现与服务降级不是同一个概念。 |
| `baseline` | 基线、稳定基线 | 表示用于比较、验证或恢复的已知状态。 |
| `source revision` | 源码版本、代码版本 | Git 项目中可进一步说明为 Git commit，但不应假设所有项目都使用 Git。 |
| `scope` | 范围、变更范围 | 指本次工作的边界。机器字段 `scope` 保持原样。 |
| `production` | 生产环境 | 对外服务的真实运行环境。不要与测试环境混用。 |
| `staging` | 预发布环境 | 仅在项目实际存在该环境时使用，不应凭术语假设环境存在。 |
| `runtime` | 运行环境、运行时 | 根据语境区分整体环境与语言运行时。 |
| `release record` | 发布记录 | 保存实际发布事实和结果，不等同于发布计划。 |
| `manifest` | 清单、制品清单 | 根据对象说明具体清单类型，机器文件名和字段保持原样。 |
| `digest` | 摘要、制品摘要 | 哈希值和算法结果保持原样，例如 `sha256:...`。 |
| `CI run` | CI 运行记录、CI 任务记录 | 保留具体平台、任务 ID 和原始状态值。 |

## 必须保留的概念区分

```text
质量门禁 != 测试验收
业务验收 != 冒烟测试
候选版本 != 待上线
构建产物 != 镜像
检查点 != 回滚版本
集成测试 != 回归测试
发布 != 部署
部署成功 != 发布完成
临时规避方案 != 根因修复
```

## 推荐表达示例

英文原意：

```text
The candidate artifact passed CI and is ready for deployment.
```

推荐表达：

```text
候选版本的构建产物已通过 CI，当前已具备部署条件。
```

英文原意：

```text
Deployment succeeded; business acceptance is still pending.
```

推荐表达：

```text
部署已成功，业务验收尚未完成；当前不能记为发布完成。
```

英文原意：

```text
The quality gate failed after the regression test.
```

推荐表达：

```text
回归测试完成后，质量门禁仍未通过。
```

英文原意：

```text
Resume from the last valid checkpoint; do not select a rollback target yet.
```

推荐表达：

```text
从最后一个有效检查点恢复执行；当前尚不需要选择回滚版本。
```

## 保留原始信息

以下内容不得为了中文化而改写：

```text
status: blocked
commit: 5624bff
artifact_digest: sha256:0123456789abcdef
error: ECONNREFUSED 127.0.0.1:3080
```

可以在其后增加中文说明，但不得替换字段名、状态值、哈希或原始错误。
